# Pull Request Process

## Purpose

Every change to AGPP is introduced through a Pull Request.

The Pull Request is the primary mechanism for reviewing and discussing engineering work.

---

## Workflow

1. Create a feature branch.

2. Implement the change.

3. Commit using Conventional Commits.

4. Push the branch.

5. Open a Pull Request.

6. Perform code review.

7. Address review comments.

8. Merge into `main`.

9. Delete the feature branch.

---

## Pull Request Requirements

Every Pull Request should include:

- Summary
- Motivation
- Scope
- Testing performed
- Related issue
- Architecture impact

---

## Review Focus

Reviewers should verify:

- architecture consistency
- readability
- maintainability
- documentation
- testing
- logging
- exception handling

---

## Merge Policy

Only reviewed Pull Requests may be merged into `main`.
